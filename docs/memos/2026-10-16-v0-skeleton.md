# v0 骨架与依赖验证

日期：2026-10-16

## 范围

v0 只做一条纵向链路：本地密码 / 飞书登录 → 订阅 source URI → worker 认领抓取入库 → 三栏时间线阅读（已读水位线、单条已读、星标）。MCP、AI 摘要、推送、通讯录同步、Collection 管理、PAT、RSS 输出都没有实现，数据表中只建了 v0 用到的部分。

## 依赖验证（Bun 1.4.2）

| 依赖 | 结论 |
| --- | --- |
| feedsmith 3 | RSS / Atom / RDF / JSON Feed 解析正常，在 Bun 下无兼容问题 |
| `@mozilla/readability` + linkedom | 可用；linkedom 的 document 类型与 DOM lib 不一致，按 `ConstructorParameters<typeof Readability>[0]` 断言 |
| sanitize-html | 可用。注意 `transformTags` 加上的属性也要在 `allowedAttributes` 里放行，否则会被再次剥掉 |
| cheerio 1 | 可用 |
| Drizzle 0.45 + pg + drizzle-kit 0.31 | 可用；`casing: 'snake_case'` |
| better-auth 1.7 | genericOAuth 的通用 provider 在 1.7 起走标准 `signIn.social({ provider })`，回调为 `/api/auth/callback/<id>`；客户端不再有 `genericOAuthClient` |
| Hono 4 RPC | 客户端响应类型不是标准 `Response`，统一用 `hono/client` 的 `parseResponse` 和 `DetailedError` |
| pino 10、croner 10、zod 4、Vite 8、TypeScript 7 | 可用 |

飞书 OAuth 端点对照官方文档确认：授权页 `accounts.feishu.cn/open-apis/authen/v1/authorize`（`client_id` + `response_type=code`，支持 PKCE），换 token 走 `open.feishu.cn/open-apis/authen/v2/oauth/token`（JSON body），用户信息 `/open-apis/authen/v1/user_info`（响应包在 `{ code, msg, data }` 里）。用户标识取 `union_id`；没有邮箱的成员用 `<union_id>@users.feishu.invalid` 占位。Lark 换成 `larksuite.com` 域名。

## 实测发现

- **fake-IP DNS**：开发机上的 Clash / Surge TUN 会把所有域名解析到 `198.18.0.0/15`（IPv6 为 `2001:2::/48`），SSRF 防护会因此拦掉全部真实源。没有关掉防护，而是加了 `MIMIR_FETCH_ALLOWED_CIDRS` 显式放行网段。
- **公共 RSSHub**：`rsshub.app` 对服务端请求返回 403，`rsshub://` 源需要自建实例（compose 里的 `rsshub` profile）。
- **OrbStack 端口**：dev Postgres 绑 `0.0.0.0` 时多个端口都报 "address already in use"，显式绑 `127.0.0.1` 后正常，端口默认 `55432`，可用 `MIMIR_DEV_PG_PORT` 改。
- **`bun test` 路径**：`bun test packages apps` 是子串过滤，会匹配到 `reference/folo/apps` 下数千个上游测试，看起来像卡住；必须写成 `./packages ./apps`。
- **Playwright 启动顺序**：`webServer` 在 `globalSetup` 之前启动，所以重建 e2e 数据库放在 webServer 命令里（`e2e/reset-db.ts`），而不是 globalSetup。

## 工程约束的取舍

- **E2E**：评估了 tester-army/e2e，没有采用：仍在 1.0 之前、默认带遥测、核心卖点是 AI agent 驱动测试，对这个项目是额外负担。只借鉴它"按用户旅程组织用例"的思路，直接用 Playwright。
- **OpenSpec**：采用（1.14，core profile，中文产出）。`openspec/specs/` 记录 5 个能力的现有行为，改变可观察行为的工作先写变更提案。OpenSpec 默认收集匿名使用统计，`bun check` 和 CI 中统一设置 `OPENSPEC_TELEMETRY=0`。
